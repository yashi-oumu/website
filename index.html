Why containers

The official Parrot images are curated, reproducible, and already carry their dependencies.

  • The host stays clean. Nothing is installed on the machine you scan from.
  • A scan is never half-broken. The image is pinned, so a library upgrade cannot break a tool mid-engagement.
  • No “works on my machine”. The tool runs where it was built and tested, every time.
  • It always matches your theme. The active Omarchy palette is read at launch, so the window belongs on the desktop.

Images pulled on demand

One binary, two front-ends

A subcommand runs headless; no arguments opens the window. The CLI needs no display, no Qt and no event loop, and every subcommand takes --json. 

$ oumu doctor
$ oumu show nmap
$ oumu schema > schema.json
$ oumu pull nmap
$ oumu build nmap --set target=10.0.0.5
$ oumu run nmap --set target=10.0.0.0/24 \
      --set top_ports=100 --json
# check the command, run nothing
$ oumu run nmap --set target=10.0.0.5 --dry-run
docker run --rm -i --network host \
  … parrotsec/nmap:latest nmap 10.0.0.5 -sS -sV

# values are type-checked before Docker is
# involved: a bad int fails immediately
$ oumu run sqlmap --set url=http://t/?id=1 \
      --set batch --set level=3 --json

Requirements

Omarchy (Arch-based) — or any Linux with Qt 6.

docker

Docker

With your user in the docker group.

qt6

Qt 6

The desktop app needs a working Qt 6 stack.

pyside6

PySide6

On Arch/Omarchy use the distro package, so the bindings match the system Qt exactly.

sudo pacman -S pyside6 && sudo usermod -aG docker $USER
